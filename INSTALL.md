# Control Center — установка и обновление

Текущий официальный Public Stable — **0.31.0**. Ветка 0.31.1 является corrective Release Candidate и не считается пользовательским Stable до завершения qualification и публикации. Поддерживаемая платформа: Linux AMD64 с systemd и PostgreSQL 15, 16, 17 или 18. При доступе из недоверенной сети требуется защищённая TLS-терминация.

## Ограничение опубликованного v0.31.0

Опубликованный файл `control-center-0.31.0-linux-amd64.tar.gz` имеет корректную SHA-256, но его payload не содержит обязательный `scripts/migrate.sh`. Публичный bootstrap и штатный updater используют migration runner из runtime archive; обход проверки вручную не допускается.

Tag и release assets `v0.31.0` считаются неизменяемыми и задним числом не переписываются.

До публикации 0.31.1 как Public Stable:

- не используйте Linux binary archive 0.31.0 как неподтверждённый вручную upgrade source;
- сохраняйте текущую работоспособную установку и её backup/recovery point;
- не сбрасывайте пользовательский пароль администратора;
- не изменяйте уже опубликованные migration-файлы;
- используйте только официальный bootstrap либо отдельно опубликованный квалифицированный exact-version procedure.

Контрольная сумма подтверждает целостность конкретного файла, но не заменяет проверку состава архива и qualification install/upgrade path.

## Требования к 0.31.1

Corrective release обязан содержать исполняемый `scripts/migrate.sh` в Linux runtime archive. До присвоения статуса Public Stable должны быть подтверждены:

1. состав и воспроизводимость фактического release archive;
2. clean-install path;
3. `0.30.x → 0.31.1` upgrade;
4. `0.31.0 → 0.31.1` update/recovery path;
5. PostgreSQL migration/restart;
6. сохранение пользовательских данных, конфигурации и установленного пароля `admin`;
7. rollback/forward-recovery;
8. security/privacy и public-source gates;
9. checksums, manifest, provenance, SBOM и third-party notices;
10. фактический публичный installer/update flow.

## Аутентификация после корректной чистой установки

При чистой установке создаётся локальный пользователь `admin` с первоначальным паролем `admin`. При первом входе пользователь обязан сменить пароль; до успешной смены обычная работа запрещена. При обновлении существующий пользовательский пароль сохраняется и не должен сбрасываться к `admin`.

## Безопасное обновление

Перед обновлением требуется рабочая резервная копия и проверяемая точка восстановления. Обновление считается успешным только после применения требуемых миграций, перезапуска сервиса и проверки health/version. При неуспешной проверке необходимо использовать предусмотренный rollback/forward-recovery path, а не вручную подменять release files.
