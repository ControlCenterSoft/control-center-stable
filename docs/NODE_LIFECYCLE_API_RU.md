# Read-only API жизненного цикла узлов Control Center 0.4

Статус: продуктовый API-контур чтения и безопасного планирования. Выполнение переходов в этой версии отсутствует.

## 1. Доступные операции

| Метод и путь | Permission | Результат |
|---|---|---|
| `GET /api/v1/nodes/{nodeId}/lifecycle` | `nodes.lifecycle.read` | Текущий объект из read-only проекции |
| `POST /api/v1/nodes/{nodeId}/lifecycle/transitions/plan` | `nodes.lifecycle.plan` | Проверенный план без записи состояния и без изменения хоста |

Роли `viewer` и `auditor` могут читать проекцию. Роль `operator` может читать и планировать. `administrator` получает доступ через существующее wildcard-разрешение. Пользователь без binding получает deny-by-default.

В текущем API используется глобальная RBAC-граница, совместимая с остальными product surfaces. Проверка delegated Site/Management Scope должна быть добавлена вместе с персистентным источником lifecycle-проекции; до этого scope-specific binding не расширяется неявно до global.

## 2. Read-only проекция

Проекция загружается как валидированный неизменяемый snapshot. Публичного метода записи у неё нет. Она:

- отклоняет невалидные и дублированные lifecycle-объекты при создании;
- возвращает значения-копии;
- безопасна для конкурентного чтения;
- повторно валидируется на HTTP-границе, включая совпадение запрошенного Node ID с `object_id` ответа адаптера;
- отвечает `404`, если lifecycle конкретного Node ID отсутствует;
- отвечает `503`, если источник проекции недоступен или небезопасен.

Control Center не выводит состояние узла из неполных legacy-данных. Пустая проекция предпочтительнее вымышленного `READY`, `OFFLINE`, `MAINTENANCE` или `RETIRED`.

## 3. Контракт планирования

Запрос содержит:

- целевое состояние `to`;
- фиксированный тип `desired` или `observation`;
- optional `reason`, обязательный для incident/retirement состояний;
- `precondition` с Node ID, прочитанной `resource_version` и optional `generation`;
- объект `evidence` со списком успешно пройденных типизированных checks.

Планировщик читает текущую проекцию, проверяет CAS-precondition, направление конечного автомата, правила `generation`, reason и все safety gates. Он создаёт стабильный `plan_id` для одной версии состояния и одного множества evidence, но не выделяет следующую production `resource_version`.

Успешный ответ всегда явно содержит:

```json
{
  "accepted": true,
  "plan_only": true,
  "host_mutation": false,
  "state_mutation": false,
  "requires_audited_change_job": true
}
```

Эти признаки являются частью схемы ответа, а не пояснительным текстом. `200 OK` означает только «запрос допустим относительно прочитанной версии проекции».

## 4. Строгая HTTP/JSON-граница

Планирующий endpoint принимает только один JSON object размером не более 64 KiB и `Content-Type: application/json`; допускается только optional `charset=utf-8`.

Fail-closed отклоняются:

- отсутствующий, другой, составной или дублированный Content-Type;
- query parameters;
- пустой body, JSON scalar/array/null;
- синтаксически повреждённый JSON;
- второй/trailing JSON value;
- неизвестные поля с учётом точного регистра;
- повторные ключи на любом поддерживаемом уровне, включая эквивалентные escaped-имена;
- `null` вместо объекта, строки, числа или массива;
- поля для password, credential, token, command, shell/exec или endpoint.

Семантически невалидный precondition/evidence возвращает `422`, устаревший precondition или запрещённый переход — `409`. Ошибки имеют стабильную оболочку `{"error":{"code":"...","message":"..."}}` и не отражают произвольное содержимое запроса.

## 5. Граница исполнения

Planning не является резервированием и не гарантирует, что состояние не изменится после ответа. Будущий исполнитель обязан:

1. создать авторизованный и аудируемый Change;
2. запустить durable Job с типизированным действием;
3. повторно прочитать lifecycle внутри транзакции;
4. атомарно повторить CAS и lifecycle validation;
5. только после этого записать новую версию и выполнять разрешённые действия;
6. зафиксировать проверку Actual State и Audit outcome.

Пока эта атомарная граница не реализована, endpoint записи lifecycle и host mutation намеренно отсутствуют.
