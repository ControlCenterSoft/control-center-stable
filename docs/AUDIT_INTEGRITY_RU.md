# Control Center — контроль целостности Audit

## Назначение

Control Center хранит административные и security-события как append-only цепочку, в которой каждое событие связано с предыдущим криптографическим хэшем. Контроль целостности подтверждает, что доступный системе последовательный префикс Audit не содержит разрыва связи или изменения уже сохранённого содержимого.

## API

`GET /api/v1/audit/integrity`

Операция является только проверкой и не изменяет инфраструктуру. Она доступна аутентифицированной учётной записи с глобальным разрешением `audit.events.read` после завершения обязательной смены первоначального пароля.

При успешной проверке возвращаются только:

- `status = verified`;
- число проверенных событий `events_checked`;
- `verified_through_hash` — хэш последнего события проверенного префикса; пустое значение допустимо только для пустого Audit.

Содержимое событий, actor/subject details, сетевые данные, credentials, session tokens и внутренние причины ошибок проверки через этот endpoint не возвращаются.

## Fail-closed поведение

Если хотя бы одно событие не соответствует своему хэшу, связь с предыдущим событием нарушена, Audit storage недоступен или проверку невозможно завершить, API не сообщает `verified` и возвращает ошибку доступности. Результат успешной проверки сам фиксируется в Audit как `audit.integrity_check`; если эту evidence-запись сохранить нельзя, успешный отчёт пользователю не возвращается.

Проверка целостности не является механизмом восстановления и не должна автоматически переписывать, удалять или «чинить» Audit. При обнаружении нарушения дальнейшее расследование и восстановление выполняются отдельно с сохранением исходного evidence.

## Граница безопасности

Проверка Audit не расширяет RBAC и не выдаёт доступ к самим событиям сверх уже назначенного разрешения. Операция не предоставляет generic SQL/shell, не изменяет Desired/Actual State и не является разрешением на какую-либо последующую mutation.
