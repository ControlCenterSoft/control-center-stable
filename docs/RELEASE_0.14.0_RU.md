# Control Center 0.14.0

Версия 0.14 продолжает advisory-only линию Capacity Planner и добавляет
детерминированное построение workload profile по ограниченному набору
нагрузочных или эксплуатационных наблюдений. Цель — превратить результаты
измерений в воспроизводимую безопасную границу планирования без автоматического
изменения инфраструктуры.

## Benchmark-backed Workload Profile

`internal/capacity/workload_profile.go` принимает набор точек нагрузки с
utilization, error rate и P95 latency для одного `scope_id` и одной единицы
workload. Входы нормализуются и сортируются по workload, поэтому одинаковый
набор evidence формирует один и тот же `profile_id` независимо от порядка
элементов.

Для каждой точки проверяется соответствие заданным SLO-границам. Результат
содержит:

- максимальную наблюдаемую нагрузку, которая ещё удовлетворяет SLO;
- рекомендуемую безопасную нагрузку после обязательного safety reserve;
- первую наблюдаемую нагрузку за SLO-границей, если такая точка есть;
- признак фактически наблюдаемой saturation boundary;
- количество SLO-conforming samples;
- confidence и состояние `ready`, `collect-evidence` или `blocked`;
- стабильную причину классификации.

## Fail-closed правила

Структурно некорректные, повторяющиеся или выходящие за допустимые числовые
границы samples отклоняются. Если после уже наблюдаемого SLO failure появляется
более высокая нагрузка, снова проходящая SLO, evidence считается немонотонным и
результат становится `blocked`. Если ни одна точка не проходит SLO, профиль также
блокируется. Если все точки проходят SLO и верхняя граница насыщения ещё не
наблюдалась, результат становится `collect-evidence`, а не выдаёт выдуманный
technical limit.

## Границы безопасности

Workload Profile является только аналитическим evidence:

- `advisory_only = true`;
- `production_mutation = false`;
- не изменяет Capacity Profile автоматически;
- не меняет Desired State или Actual State;
- не выполняет placement, drain, resize, migration или rebalance;
- не запускает provider-команды;
- не изменяет сеть, хранилище или workload policy;
- не инициирует закупку оборудования.

Добавлены модульные проверки детерминированности, подтверждённой SLO-границы,
режима дополнительного сбора evidence, блокировки немонотонных измерений,
блокировки при отсутствии пригодной точки и отклонения неоднозначных samples.
JSON contract закрыт к неизвестным полям и отдельно фиксирует отсутствие
production mutation.
