# Control Center 0.9.0

Статус: кандидат разработки, не официальный релиз.

Версия 0.9 продолжает Capacity & Placement Advisor после прогнозирования,
what-if анализа и advisory placement предыдущих версий и добавляет отдельный
детерминированный отчёт по узким местам парка.

## Bottleneck Report

`internal/capacity/bottleneck.go` формирует read-only оценку для здоровых узлов,
которые уже несут требуемую роль. Для каждого узла сопоставляются два независимых
резерва:

- резерв безопасной ёмкости относительно текущей нагрузки;
- резерв по фактически ограничивающей метрике Capacity Profile.

Эффективным резервом считается более строгая из этих двух границ. Это позволяет
не считать узел безопасным только потому, что общий workload ещё помещается в
номинальную ёмкость, если CPU, память, хранилище или другая наблюдаемая метрика
уже подошла к своей безопасной границе.

## Классификация

Отчёт использует четыре состояния:

- `critical` — эффективный резерв достиг критической границы;
- `warning` — резерв ниже предупреждающей границы;
- `unknown` — исходные данные имеют недостаточную достоверность;
- `healthy` — заданный резерв сохраняется.

Для каждого finding фиксируются узел, ограничивающая метрика и target,
capacity reserve, metric reserve, effective reserve, confidence, severity и
стабильная причина классификации. Findings сортируются детерминированно, а
`report_id` воспроизводим для одного и того же набора входных данных независимо
от порядка узлов.

## Отказоустойчивость и рекомендации

Перед формированием итогового действия повторно используется общий
`BuildAssessment`, поэтому bottleneck-анализ учитывает заданный резерв отказа
узлов, а не рассматривает каждый сервер изолированно.

Рекомендательное действие выбирается fail-closed:

- небезопасный парк или критическое узкое место → `add-role-capacity`;
- недостаточная достоверность данных → `collect-evidence`;
- только предупреждающие узкие места → `adjust-workload-policy`;
- достаточный резерв → `none`.

Низкая достоверность не преобразуется в автоматическое решение о покупке,
переносе роли или изменении конфигурации.

## Границы безопасности

Bottleneck Report остаётся исключительно аналитическим:

- `advisory_only = true`;
- `production_mutation = false`;
- алгоритм не меняет Desired State и Actual State;
- не назначает и не переносит роли;
- не запускает jobs и provider-команды;
- не изменяет сеть, хранилище или workload policy;
- не выполняет закупку или масштабирование автоматически.

Версия 0.9 сохраняет накопленные гарантии Capacity Planner: безопасную ёмкость и
прогнозирование 0.7, what-if моделирование, отказоустойчивую assessment-модель и
advisory placement 0.8. Официальный выпуск 0.9.0 допускается только после
успешной полной qualification, точного дополнительного review и release gates.
